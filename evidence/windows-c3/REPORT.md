## Runner findings

### W01 — failure exits are swallowed

The Python helper always returns 0 after writing evidence, even when proc.returncode is nonzero. The BAT checks the helper exit, so it prints Done and exits 0 for a failing suite.

A controlled separate fixture contained one intentionally failing unittest. With the unmodified T Python/BAT files: child test exit 1, attempted 1, failures 1, BAT exit 0. This fixture was not the C3 suite and did not change C3 code.

[Negative-control result](evidence/tooling-negative/result.json) · [Raw failing fixture log](evidence/tooling-negative/failing-suite.log) · [Launcher output](evidence/tooling-negative/launcher-console.log).

### W02 — the commit label is caller-supplied, with no source preflight

The same fixture had an empty control_room directory and none of the six expected source files. The helper still ran, wrote code_commit_under_review=C3 from the argument, listed all six missing files and returned 0. It does not compare actual Git HEAD, expected source pins, source dirty state or before/after hashes.

This does not invalidate this reviewer's actual C3 Windows run: the separate independent receipt establishes the real C3 source bytes. It means the helper manifest alone cannot establish code identity for future runs.

[Negative helper manifest](evidence/tooling-negative/helper-manifest.json) · [Reproducer](tooling_checks.py).

### W03 — repeatability and metadata need tightening

Log names use only the date and the manifest has one fixed filename, so repeated runs into the same directory overwrite evidence. The helper records its own sys.version even if --python selects another interpreter. stdout and stderr are concatenated after the child exits, so their original interleaving is not preserved. These are source-level observations; the actual run used one fresh directory and the same interpreter for helper/child, so its evidence remains interpretable.

Required tooling repair: unique immutable run directories; fail-closed source checks; actual selected interpreter metadata; authoritative counts; raw stream preservation; and nonzero propagation on test/collection/preflight failure. Preserve artifacts even when tests fail.
